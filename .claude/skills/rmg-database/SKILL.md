# RMG database: layout, estimation, choosing libraries, tracing sources

Based on the 2025 RMG Workshop talk “RMG Database and Parameter Estimation” and RMG-Py 3.3.0.

- `$RMG_DB` means the RMG-database checkout. It is usually a sibling of RMG-Py. In Docker it is `/rmg/RMG-database`. The `rmg-install` skill explains how to detect it.
- RMG reads `settings['database.directory']`, which is `$RMG_DB/input`. Check it with:
  `python -c "from rmgpy import settings; print(settings['database.directory'])"` (add `PYTHONPATH=$RMG_PY` if needed).
- To add or change data, use the `rmg-add-data` skill. **Never edit the shared database without telling the user.**

## 1. Layout (`$RMG_DB/input/`)

| Path | What it is |
|---|---|
| `thermo/libraries/<Name>.py` | **Thermo library**: exact values for specific species. Matching is by structure, not by label. |
| `thermo/groups/group.py` | Group-additivity tree for closed-shell species: about 60k lines, with the `tree()` at the bottom. |
| `thermo/groups/radical.py` | HBI corrections for radicals. |
| `thermo/groups/ring.py`, `polycyclic.py`, `other.py`, `longDistanceInteraction_*.py` | Ring, polycyclic, gauche and other corrections. |
| `thermo/groups/adsorption{Pt111,Ni111,Li}.py` | Adsorbate corrections for surface species. |
| `thermo/depository/{stable,radical}.py` | Reference data. It is not searched during a normal run. |
| `kinetics/libraries/<Name>/{reactions.py,dictionary.txt}` | **Reaction library**. Names can be nested, e.g. `Glarborg/C3` or `Surface/CPOX_Pt/Deutschmann2006_adjusted`. |
| `kinetics/families/<Family>/groups.py` | **Family**: the recipe, template, group entries and `tree()`. |
| `kinetics/families/<Family>/rules.py` | Rate rules at tree nodes. |
| `kinetics/families/<Family>/training/{reactions.py,dictionary.txt}` | **Training reactions**: library-like entries whose atoms are labelled `*1 *2 ...` per the recipe, each with a `rank`. |
| `kinetics/families/recommended.py` | Named family sets: `default`, `ch_pyrolysis`, `liquid_peroxide`, `surface`, `halogens`, `surface_development`, `electrochem`. |
| `transport/`, `statmech/`, `solvation/`, `surface/libraries/metal.py`, `quantum_corrections/data.py`, `reference_sets/`, `forbiddenStructures.py` | Lennard-Jones data, frequency groups for pdep, solvation, metal binding energies, Arkane AEC/BAC, isodesmic reference sets, and globally forbidden structures. |

Vocabulary:
- **Library**: specific species or reactions only. It never extrapolates.
- **Group / family**: generalizes to species and reactions RMG has never seen.
- **Training**: the data the family trees are fitted to.
- **Depository**: reference data, such as `thermo/depository` and `families/*/NIST`.

## 2. List what is installed (do this before recommending a library)

```bash
RMG_DB=/path/to/RMG-database          # Docker: /rmg/RMG-database
ls $RMG_DB/input/thermo/libraries/ | sed 's/\.py$//'                       # thermo libraries
find $RMG_DB/input/kinetics/libraries -name reactions.py \
  | sed "s#$RMG_DB/input/kinetics/libraries/##; s#/reactions.py##" | sort   # reaction libraries (nested names)
ls $RMG_DB/input/kinetics/families/                                          # families
grep -l "autoGenerated *= *True" $RMG_DB/input/kinetics/families/*/groups.py \
  | xargs -n1 dirname | xargs -n1 basename                                   # auto-generated (Blowers-Masel) families
head -30 "$RMG_DB/input/thermo/libraries/CBS_QB3_1dHR.py"                    # read a library's description
```
- Library names are **case-sensitive** and must match the file or folder name. For example, `thermo_DFT_CCSDTF12_BAC` is correct and `...CCSDTf12...` is wrong.
- A short catalog of commonly used libraries, with entry counts, is in [reference/libraries.md](reference/libraries.md).
- The rmg.mit.edu database browser shows the same data (see `rmg-website`). The website runs a newer database than this checkout.

## 3. How RMG gets thermo (`rmgpy/data/thermo.py` `get_thermo_data`)

1. **Thermo libraries, in the order listed in `thermoLibraries`. The first match wins.**
2. For a radical, RMG looks up the saturated parent in the libraries and applies the HBI correction from `radical.py`. It does this for each resonance structure.
3. QM (`quantumMechanics`, rarely used) or the ML estimator, if enabled. **The ML estimator does not work in this version.**
4. **Group additivity (GAV).**
   - For each heavy atom, RMG descends the `group.py` tree to the most specific matching node.
   - A node holds data, or `None`, or a **string naming another node** that it borrows from.
   - RMG then adds ring, gauche and other corrections.
   - Radicals are built as the saturated parent plus HBI.
   - GAV is less accurate for radicals and for unusual or polycyclic species.

Two more points:
- **Always include `primaryThermoLibrary`.** H and H2 cannot be estimated by GAV.
- Surface species use the gas-phase precursor, plus adsorption groups, plus linear scaling to the chosen metal (see `rmg-catalysis`).

## 4. How RMG gets kinetics (`documentation/source/users/rmg/kinetics.rst`)

Priority order:
1. **Seed mechanisms**, in the order listed. *All* their species and reactions go straight into the **core**.
2. **Reaction libraries**, in the order listed. Their reactions go into the **edge**. They enter the core only if their species do. A library reaction overrides family-generated copies of the same reaction.
3. **Training reactions** that match exactly.
4. **Rate rules / tree nodes.** For hand-built trees: exact rules, then rules by rank, then averaged rules.

Two kinds of family:

| | Hand-built families | Auto-generated (Blowers-Masel, "BM") families |
|---|---|---|
| How to tell | no `autoGenerated` flag in `groups.py` | `autoGenerated = True` in `groups.py`. 44 of the 126 local families, e.g. R_Recombination, Disproportionation, Intra_R_Add_Endocyclic, Retroene, Ketoenol, 2+2_cycloaddition |
| Trees | one tree per reactant. Bimolecular families have 2 (R_Addition_MultipleBond: `R_R`, `YJ`). Unimolecular families usually have 3 (intra_H_migration: `RnH`, `Y_rad_out`, `XH_out`) | a single `Root` tree with machine-made node names (`Root_Ext-1R!H-R_N-4R->O...`) |
| Rules | at every database load, RMG adds rules from training and then averages up the tree (`rmgpy/rmg/main.py`). The A factor is averaged geometrically. n, Ea and α are averaged arithmetically. | `ArrheniusBM` rules fitted **offline**, so Ea depends on ΔH_rxn, each with a `RateUncertainty`. They are **not** refit at load time. |
| Examples | H_Abstraction, R_Addition_MultipleBond, intra_H_migration (still hand-built here) | see the `grep` in §2 |

More points:
- Group additivity for kinetics has been removed. Ignore it in old training material.
- **Rank** of training and rule entries (lower is better): 1 = experiment/FCI, 2 = W4/HEAT, 3 = CCSD(T)-F12/TZ or better, 4 = CCSD(T)-F12/DZ, 5 = CBS-QB3 with 1-D rotors, 6 = double-hybrid DFT, 7 = hybrid DFT, 8 = B3LYP or lower, 9 = guess, 10 = average of rates, 0 = never used. When several entries sit at the same node, the best rank wins.
- Reverse rates always come from thermo. Thermo errors therefore become kinetics errors.

## 5. Choosing libraries: decision rules

- **List order is priority.** The first library containing a species or reaction wins. Put the most trusted and most system-specific libraries first. This applies to `thermoLibraries`, `reactionLibraries` and `seedMechanisms`.
- **Pair a mechanism with its own thermo.** If you seed or use the kinetics of `GRI-Mech3.0`, `FFCM1(-)`, `Klippenstein_Glarborg2016` or `NOx2018`, list the thermo library of the same name near the front. The reverse rates were built on that thermo. This was the workshop advice, and see `examples/rmg/e85/input.py`.
- **Seed or reaction library?**
  - Use a seed (`seedMechanisms`) for small core chemistry you know matters. Example: H2/O2 for any oxidation, `primaryH2O2` or `BurkeH2O2inN2`.
  - Use a reaction library for chemistry that should enter only if RMG finds it important.
  - Don't seed oxidation chemistry into pyrolysis models (docs).
  - `('LibName', True)` in `reactionLibraries` also writes the library's unused edge reactions into the Chemkin file.
- **Families:** `kineticsFamilies='default'` suits most gas-phase C/H/O work.
  - Use `['default', 'surface']` for catalysis.
  - Add `'halogens'` or `'ch_pyrolysis'` when they apply.
  - `['!FamilyName']` excludes families. You cannot mix `!` and non-`!` names.
- `kineticsDepositories='default'` means `['training']`. Use `['!training']` to ignore the training sets.
- A typical C/H/O oxidation start, from `examples/rmg/commented/input.py`:
  ```python
  database(
      thermoLibraries=['BurkeH2O2', 'primaryThermoLibrary', 'DFT_QCI_thermo', 'CBS_QB3_1dHR'],
      reactionLibraries=[],            # e.g. [('C3', False)]
      seedMechanisms=['primaryH2O2'],
      kineticsDepositories=['training'],
      kineticsFamilies='default',
      kineticsEstimator='rate rules',
  )
  ```
- Choosing libraries is partly judgment. Read each library's header (source, level of theory, bath gas) and ask the user what their community uses. Check that every name exists locally (§2).
- For external libraries outside the database (by path), see `rmg-add-data`.

## 6. Tracing where a parameter came from

1. **`chemkin/chem_annotated.inp`**: every species and reaction has `!` comments above it.
   - Thermo:
     - `! Thermo library: DFT_QCI_thermo`
     - `! Thermo library: primaryThermoLibrary + radical(CH3)` (library parent plus HBI)
     - `! Thermo group additivity estimation: group(Cs-CsHHH) + ... + radical(CCJ)` (GAV)
   - Kinetics:
     - `! Library reaction: GRI-Mech3.0` (library or seed)
     - `! PDep reaction: PDepNetwork #7`
     - `! Template reaction: H_Abstraction` (family), followed by one of:
       - `Matched reaction 212 ... in H_Abstraction/training` (exact training match)
       - `Exact match found for rate rule [...]`
       - `Estimated using template [...] for rate rule [...]` / `Estimated using an average for rate rule [...]` / `Euclidian distance = N` (hand-built tree; a larger distance means a poorer match)
       - `Estimated from node Root_... in family Disproportionation.` / `BM rule fitted to N training reactions at node ...` (BM tree)
       - `Multiplied by reaction path degeneracy N`
   - Quick triage:
     ```bash
     grep -c "Thermo group additivity" chemkin/chem_annotated.inp     # how many species are GAV estimates
     grep -E "^! (Library reaction|PDep reaction|Estimated|Matched reaction|Exact match|BM rule)" chemkin/chem_annotated.inp \
     | sed -E 's/ (using|for|in|at|from|node|[0-9]|\[).*//' | sort | uniq -c | sort -rn    # kinetics source mix
     ```
   - Set `options(verboseComments=True)` for longer kinetics comments.
2. **`python rmg.py -k input.py`** (`--kineticsdatastore`) writes `kinetics_database/<family>.txt`, which lists the sources behind each rate rule.
3. **`ipython/find_parameter_sources_and_assign_uncertainties.ipynb`** uses `rmgpy.tools.uncertainty.Uncertainty`: `load_model(chem_annotated, species_dictionary)`, then `load_database(...)` with the *same* libraries as the run, then `extract_sources_from_model()`. It prints the library, GAV groups or rate-rule template for every parameter. The database version must match the one used for the run.
4. **Re-estimate one species or reaction locally.** The `rmg-website` skill has tested scripts for thermo and family kinetics. They show the source comment and every library value.
5. Then judge the value:
   - Is the library's level of theory adequate?
   - Is the GAV node generic, or a string reference to another node?
   - For a BM tree, is the node `RateUncertainty` large?
   - For a hand-built tree, is the Euclidian distance large?
   - Sensitive parameters estimated this way are candidates for new data (`rmg-add-data`, `arkane`).

## Gotchas

- In `RMGDatabase().load(...)`, `surface=False` also **skips loading thermo** in 3.3.0 (`rmgpy/data/rmg.py`). Keep `surface=True` when you script against the database.
- The commented example input says earlier libraries "overwrite" later ones. What actually happens is that **the earlier-listed library wins**.
- Old docs show adjlists like `1 C 0` and `kineticsFamilies='defult'`. Use the modern syntax and `'default'`.
- A training reaction added to a **BM family** changes nothing until the tree is refit (`rmg-add-data`). At best, that exact reaction picks up its own training value.
- Loading `kineticsFamilies='all'` or every library is slow. When scripting, load only what you need.

When unsure, the source of truth is `rmgpy/rmg/input.py` (`database()`), `rmgpy/data/thermo.py`, `rmgpy/data/kinetics/{database,family}.py`, `rmgpy/rmg/main.py` (`load_database`), and `documentation/source/users/rmg/{input,kinetics,thermo}.rst`.
